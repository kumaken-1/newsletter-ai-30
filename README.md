# 生成AI 30のチャレンジⅨ ～学級通信・学年通信～

**公開ページ: https://kumaken-1.github.io/newsletter-ai-30/**

学級通信・学年通信をAIに丸ごと書かせるのではなく、教師が実際に見た子どもの姿や出来事を材料に、AIと「選ぶ・整理する・意味を考える・短くする・読み直す」というやり取りを経験する30回です。実際に職員室で出た困りごと（通信を書こうとしても何も浮かばない、「優しい姿が見られました」と書きそうになる、書き上げると「先生が書いた文章」すぎる、など）をもとに構成しています。気になる回を、ひとつ試すところから始められます。

**この講座の目的は、通信をAIに代筆させることではありません。**教師が見た事実から始め、AIとのやり取りで一つ書き方の判断を進めることを1回の単位にしています。

## 参加のしかた

- 自由参加です。30回すべてをやる必要はありません。
- 順番も速さも自由です。1日に何回やっても、間があいてもかまいません。
- ランキング、提出、成績評価はありません。取り組んだ数を競う企画でもありません。
- 一人で試せる回（自分の文章を読み直す、見出しの付け方を変える）と、子どもや家庭とのやり取りが材料になる回（発言メモを整理する、通信を読み返してもらう）の両方があります。
- 生成AIを開けないときは、文章を読んで「どんな回答が来そうか」を考えるだけでも参加できます。

## 1つの回の進み方

回をひらくと、次の順で並んでいます。**手順の番号は1回目から最後まで通しで振ってあります。**

1. **1回目に送る** — 生成AIに送る文章と、そこまでの手順
2. **回答が来ます** — 何を見ればよいかを1行で書いています。ここがその回のねらいです
3. **2回目に送る** — 空欄を自分の言葉でうめて、新しいメッセージとして送ります

添付や貼り付けが必要な回は、**添付と文章が同じメッセージで、送信は1回**であることを手順に明記しています。

**10回講座（Ⅰ）と校務版（Ⅱ）と同じ進み方です。** シリーズを通して操作の型を変えていません。参加するたびにやり方を覚え直さずにすむためです。

### 3回目がある回が3つあります

30回のうち3回だけ、2回目のあとに**3回目（任意）**があります。2回目で見えたことをもとに自分が決めたことを書き、その判断で失われるものをAIに挙げさせる回です。

**ここで止めてもかまいません。**そのことは画面と手順の両方に書いてあります。2回目で完結する形は崩していません。

3回目でAIに求めるのは反証だけです。「私の判断をほめる言葉は書かないでください」と入れてあります。**決めるのは教師で、試すのがAIです。**

### 1回目の文に空欄がある回があります

30回のうち16回は、1回目に送る文そのものに空欄があります。「行事中に見た場面は『____』です」のような形で、そこに自分の見立てを書いてから送ります。

**記入欄を別に立てていません。** 自分の見立てを書く行為と、送る文を組み立てる行為が同じ1つの操作になります。AIの出力を先に読んでから考えるのではなく、自分の考えを先に置いてAIに当てる形です。

### AIの回答を短くしています

**AIに送る文には、全30回とも次の制約が付いています。**

> Web検索はせず、ここに書いた情報だけを使ってください。各項目は2文以内で書いてください。

一覧やメモを渡す回には、さらに「貼った内容にない一般論は足さないでください」（資料を添付する回は「資料にない一般論は足さないでください」）が付きます。

この制約がないと、AIは外部サイトを検索して長い回答を返します。長く整った回答と、検索してきた権威ある記述は、教師の判断を弱めます。この講座で必要なのは詳しい助言ではなく、短時間で吟味できる分量の回答です。

制約は回ごとの本文ではなく `js/view-model.js` の `PROMPT_LIMITS` にあります。30回すべてに同じ文が付くため、回ごとに書き分けません。

### 使わないという判断も結論です

回答を読んだら、採用するか、直すか、使わないかを決めます。**使わないという判断も、その回の結論です。**

この判断は画面のボタンではなく、文で伝えています。選択肢を押させる仕組みにすると、Ⅰ・Ⅱと操作の型が変わってしまうためです。

### 最後にひとつだけ試すことを書き留めます

各回の終わりに、**次の一号でひとつだけ試すこと**を一行だけ書き留めます。通信を作り直すのではなく、どこを見るか、何を削るか、誰の言葉を残すかのような、次の一号でそのままできる形にします。

**書く場所はこの画面ではなく、手元の手帳です。** 画面に記入欄を置いていないのは、子どもの記録に触れた言葉を端末に残さないためです。

## 大切にしていること

生成AIの回答は「正解」や「完成品」ではなく、考えるための材料です。採用するか、直すか、使わないかを決めるのは教師です。

**AIに任せないことを、はっきり決めてあります。**

- 通信の文章そのものをAIに書かせ、代筆にすること。**AIに求めるのは、材料を選ぶこと、整理すること、事実と解釈を分けること、読む側の目線を示すことまでです。**
- 子どもの性格や家庭背景、内面をAIに断定させること
- 実際にはない出来事やエピソードをAIに作らせること
- 発行回数や文章量を増やす方向へ話を進めること
- 連絡事項と、子どもの今を家庭と共有することを混同すること

### 事実と教師の解釈を分けます

子どもの姿を言葉にする回では、**「実際に起きたこと」と「教師である私が意味づけたこと」を分けさせます。**「成長した」「優しい」で簡単に閉じてしまうと、その子が実際に何をしたのかが読み手に伝わりません。分けて見ることで、事実として書ける部分がどこまでかが具体的に見えます。

### 子どもの性格・家庭背景をAIに断定させません

子どもの発言や沈黙を扱う回は、性格診断や家庭の事情の推測に踏み込みやすい性質があります。**この巻ではその踏み込みを禁じ手にしています。**AIに求めるのは、考えられる複数の見方を挙げることまでで、どれか一つに決めつけることではありません。

## 扱う5つの群

| 群 | 回数 | 例 |
|---|---|---|
| 何を書けばいい？ | 6 | 何も浮かばない、書きたいことが多すぎる、大きな出来事がない週 |
| この姿、どう伝える？ | 6 | 美談にせず事実を残す、性格の言葉を使わない、成長を言い切らない |
| 保護者には、どう届く？ | 6 | 先生の文章すぎる、お願いが命令みたいになる、読む側から読み直す |
| 一号で終わらせない | 6 | 各クラスの出来事を並べるだけでよいか、担任ごとの雰囲気の違い、前年度との使い回し |
| そもそも、この通信どうする？ | 6 | 長くなりすぎる、テンプレート化、発行頻度そのものの問い直し |

**この巻は代筆の練習ではありません。**通信作成チーム（構成・執筆・校閲のエージェント）とは思想が逆で、教師自身が書く力を、AIとのやり取りを通して確かめる巻です。

## 散りばめてある対話の型

30回のケースには、生成AIとのやり取りをうまくするための型がいくつも仕込んであります。読み進めるうちに自然と身につきますが、先に知っておきたい人のために挙げておきます。

- **先に自分の考えを書く** — AIの答えを読む前に、空欄に自分の見立てを書きます。AIの言葉に引っ張られないためです。
- **「〜しないでください」で縛る** — AIに結論や評価を決めさせないよう、してほしくないことを先に伝えます。
- **事実と解釈を分けさせる** — 「成長した」「優しい」のような言葉でまとめず、実際に起きたことと自分の意味づけを分けて確かめます。
- **読む側の立場から読み直させる** — 書く側の目線に偏らないよう、保護者としてどう読めるかを確かめさせます。
- **決めてから反証を求める** — 自分で決めたことを伝えて、それで失われるものを挙げさせます。後押しの言葉は求めません。

## 操作の種類と色

「そのままコピーすればよいのか、自分で何か足すのか」が分かるように、操作の種類ごとに色とラベルを分けています。

| 色 | ラベル | 利用者がすること |
|---|---|---|
| 黄 | 空欄をうめてから送る | 文の空欄に、自分の考えを書いてから送る |
| 緑 | 自分の文を貼ってから送る | メモや文章の一覧を書き出して貼り付けてから送る |
| 紫 | 資料を添付してから送る | 通信の下書きや前年度の通信を添付してから送る |
| 赤 | 注意 | この色は注意以外で使いません |

**そのままコピーして送るだけの回はありません。** 自分の学級・学年の様子が入らない回は、誰にも当てはまらない一般論になるためです。

色は2番目の手がかりです。**ラベルとアイコンだけで何をするか決まる**ようにしてあるので、色の見分けが難しい人でも困りません。

## くわしく

実際に詰まる4か所にだけ、補足を用意しています。回ごとに書き分けず、共通の4本を参照しています。

- 添付ボタンの場所
- 1回で送る
- 新しいメッセージ
- 貼り付け

補足は**押しても、マウスを乗せても開きます**。マウスのない携帯やタブレットでも読めるようにするためです。

## 印刷して使う

[`print.html`](./print.html) が印刷用の一覧です。**A4縦2列で刷ります。**1ページに2回分が載ります。校務版（Ⅱ）と同じ紙面です。

1回分が2ページに分かれることはありません。必要な回だけ刷りたいときは、ページ番号を指定してください。

紙面には、画面と同じ順で全部載っています。3回目がある回は、紙面にも3回目が出ます。**記入欄は置いていません。** 書き留めるのは手元の手帳です。

## 記録

「やってみた」の印だけを、利用中の端末に保存します。件数や達成率、ごほうびの仕組みはありません。

## プライバシーとデータ

- 児童・保護者・職員の氏名、顔、連絡先、学習の記録、健康に関する情報などの個人情報を入力・撮影・添付しないでください。
- 資料を渡す回では、**個人が分かる情報を取り除く手順を、資料を渡す前の手順として示しています。** 子どもの名前は「児童A」などに置き換え、学校名や同僚の名前も外します。
- 練習には、同梱の練習用素材を使ってください。
- 入力欄は、送る文の空欄だけです（2回目は全30回、1回目は空欄をうめて送る16回、3回目がある3回）。書いた言葉はこのサイトの外へ送らず、**端末にも保存しません。**画面を閉じると消えます。
- 「やってみた」の印だけを `localStorage` に保存します。入力内容や生成AIの回答は収集しません。**保存のキーは巻ごとに分けてあります。**シリーズの全巻が同じドメインで公開されているため、キーを分けないと記録が混ざります。
- 外部API、アクセス解析、広告、トラッカーは使用しません。生成AIサービスとの通信もこのサイトからは行いません。

この巻は子どもの発言メモや通信の下書きを渡す場面が多くなります。そのため、入力欄の内容を一切保存せず、書き留める場所も画面の外に置いています。

### 練習用の素材

資料を貼ったり添付したりする回では、探す手間で止まらないよう練習用の素材を同梱しています。すべて架空の内容で、実在の学校・自治体・団体・人物とは関係ありません。子どもの名前にあたる部分は「児童A」などの役割名に置き換えてあります。**サイトのトップページからも開けます。**

- `assets/sample-kodomo-kibou.md`：架空の子どもの発言・行動メモ（性格の決めつけが混ざっている形）
- `assets/sample-gakkyukai-kiroku.md`：架空の保護者へのお願い文（命令口調になっている形）
- `assets/sample-gyoji-junbi.md`：架空の学級通信の下書き（連絡事項だけで埋まっている形）
- `assets/sample-furikaeri-kanso.md`：架空の学年通信の下書き（クラスごとに文章の雰囲気が違う形）
- `assets/sample-hanseikai-iken.md`：架空の前年度の通信（日付を変えればそのまま使えそうな形）

**この5件には、職員室で失敗しやすい形をわざと入れてあります。** 良い例ではありません。直すところを探す練習に使ってください。

## 使い方

### GitHub Pages

公開後はURLをブラウザで開くだけで使えます。携帯にも対応しています。

### ローカルで見る

このリポジトリを取得し、プロジェクト直下で静的ファイルを配信します。

```powershell
python -m http.server 4173
```

その後、`http://localhost:4173/` をブラウザで開きます。ビルドツールやAPIキーは不要です。

## 開発・確認

Node.js 22以降を想定しています。

```powershell
npm test
npm run build:print
```

- `npm test`: 内容、記録、画面構造、印刷用ページ、公開文書のテスト
- `npm run build:print`: `js/challenges.js` から印刷用の `print.html` を再生成

## 内容を更新する

本文の正本は [`js/challenges.js`](./js/challenges.js) です。更新後は `npm run build:print` を実行し、画面と印刷用ページの内容をそろえてから `npm test` を実行してください。生成済みの `print.html` を直接編集しないでください。

1回分は7つの項目を持ちます。`id` `category` `title` `intro` `send` `reply` `followUp` です。3回目がある回だけ、8つ目に `deepen` が付きます。`deepen` は `reply` `template` `hints` の3つを持ちます。10回講座・校務版と同じ構造で、`send` に `fill`（空欄をうめてから送る）が加わり、任意の `deepen` が増えただけです。`fill` の回は `send.hint` に空欄へ入れる語の例を持ちます。

改善提案や誤りの報告は、公開リポジトリのIssueまたはPull Requestで歓迎します。実在する児童・保護者・職員や学校内部の情報は、Issue、Pull Request、サンプルデータ、画像のいずれにも含めないでください。
